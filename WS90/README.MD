# Shelly WS90 (EcoWitt) шаблон для SprutHub через Zigbee2MQTT

Шаблон устройства **Shelly WS90 (EcoWitt Weather Station)** для **SprutHub** при подключении через **Zigbee2MQTT (MQTT)**.

Шаблон позволяет добавить метеостанцию в SprutHub с отображением основных погодных параметров, дополнительных вычисляемых показателей, публикуемых Zigbee2MQTT, а также статуса связи с самим мостом Zigbee2MQTT.

Каталог SprutHub: https://sprut.ai/catalog/item/meteostanciya-ecowitt-ws90 (catalogId: 5948)
Обсуждение/issue: https://github.com/sprut/Hub/issues/4700

## Установка

1. Скопируйте файл шаблона устройства (`Шаблон устройства - mqtt (Shelly) + Ecowitt WS90.json`).
2. Импортируйте его в SprutHub:
   ```
   Настройки → Шаблоны устройств → MQTT → Импорт
   ```
3. Убедитесь, что имя устройства в Zigbee2MQTT соответствует шаблону WS90.
4. Запустите поиск в контроллере MQTT — устройство автоматически появится в SprutHub.
5. Откройте добавленный аксессуар и определите его реальные `accId` / `sId` / `cId` (номера аксессуара, сервисов и характеристик) — они выдаются SprutHub заново при каждом импорте и **не совпадают** с теми, что зашиты в сопутствующих сценариях (см. ниже).
6. Импортируйте три сопутствующих сценария (`Блочный → Шаблоны → импортировать`) и поправьте в них номера `aId`/`sId`/`cId` под свои — см. раздел «Сопутствующие сценарии».

## Особенности

- Давление автоматически переводится из hPa в **мм рт. ст.**
- Скорость и порывы ветра округляются до целого значения.
- Освещённость корректируется для совместимости с HomeKit.
- Статус погоды автоматически переводится на русский язык.
- Направление ветра дополнительно выводится текстом (8 румбов: Север, Северо-Восток, Восток, Юго-Восток, Юг, Юго-Запад, Запад, Северо-Запад), вычисляется из градусов по `wind_direction`.
- Для батареи отображается предупреждение при уровне менее **20%**.
- Статус связи (`C_Online` в `AccessoryInformation`) отслеживает **весь мост Zigbee2MQTT** через его собственный LWT-топик `zigbee2mqtt/bridge/state`, а не доступность конкретно WS90 — это осознанный выбор: встроенная функция availability самого z2m для батарейных устройств по умолчанию ждёт 25 часов тишины, что слишком медленно для практической диагностики зависания моста.
- Версия прошивки прописана в шаблоне статично (`FirmwareRevision`), т.к. WS90 не публикует её в MQTT.

## Сопутствующие сценарии

Для полноценной работы шаблона (усреднение показателей и уведомление о зависании станции) нужно импортировать три сценария. Во всех них **зашиты конкретные `accId`/`sId`/`cId`** (например, `537`, `40`, `42`) — их нужно поправить под свои значения после импорта устройства, иначе сценарии будут читать/писать не те характеристики.

### 1. `Метеостанция WS90.json` (тип BLOCK)
Основной блочный сценарий:
- Переименовывает сервис датчика дождя в «Идёт дождь» / «Нет дождя» по `rain_status`.
- Раз в 30 минут запускает пересчёт среднего УФ (`global.uv_calc()`) и среднего ветра (`global.wind_calc()`).
- Копит значения УФ и скорости ветра по каждому обновлению (`global.uv_tick()`, `global.wind_tick()`).
- Сбрасывает УФ в 0, если больше часа нет солнца (значение не растёт от 0).
- Если по ключевым характеристикам (температура, влажность, освещённость, УФ и др.) больше **4 часов** нет обновлений — присылает push-уведомление: «Метеостанция не передает данные, нажмите кратковременно 1 раз Reset на устройстве».

### 2. `Средняя скорость ветра.json` (тип GLOBAL)
Копит сумму и количество показаний скорости ветра (`wind_tick`), раз в 30 минут считает среднее и записывает в характеристику «Средняя скорость ветра» (`wind_calc`).

### 3. `УФ Средний.json` (тип GLOBAL)
Аналогично — копит показания УФ-индекса (`uv_tick`), раз в 30 минут считает среднее и записывает в характеристику «Средний УФ индекс» (`uv_calc`).

## Известные ограничения

Данный шаблон предназначен для подключения **через MQTT (Zigbee2MQTT)**.

При прямом подключении устройства к встроенному Zigbee-контроллеру SprutHub в некоторых версиях прошивки Shelly могут возникать проблемы с нестандартными manufacturer-specific кластерами (`FC01`, `FC02`, `FC03`).

Статус связи (`C_Online`) отражает состояние связи **z2m ↔ MQTT-брокер**, а не связь **z2m ↔ Zigbee-координатор**. Если сам процесс Zigbee2MQTT жив и подключён к брокеру, но завис USB-радиомодуль/координатор, статус останется «Online», хотя данные от станции реально перестанут поступать.

Сценарии содержат зашитые числовые ID аксессора/сервисов/характеристик конкретной установки автора — при переносе на другую систему SprutHub их нужно скорректировать вручную (см. раздел «Сопутствующие сценарии»).
